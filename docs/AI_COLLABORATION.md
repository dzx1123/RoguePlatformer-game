# Codex × Grok Bot 协作规则

目标：让 Grok Bot 负责独立审查和下一步拆解，Codex 负责实现、测试与交付；通过共享文件减少人工转述，同时避免两个代理同时修改同一份代码。

## 唯一工程目录

- 唯一有效路径：`D:\Godot\RoguePlatformer-game`
- 废弃路径：`D:\RoguePlatformer-game`
- 禁止读取、修改、测试、构建或重新创建废弃路径。

## 文件所有权

| 范围 | 负责人 | 规则 |
| --- | --- | --- |
| `scripts/`、`scenes/`、`assets/`、`tests/`、项目配置 | Codex | 唯一代码写入方；负责实现与回归 |
| `docs/GROK_REVIEW.md` | Grok Bot | 唯一允许 Grok Bot 写入的项目文件 |
| `docs/CODEX_HANDOFF.md` | Codex | 每轮完成后更新当前基线和待审任务 |
| 其他 `docs/` | Codex | 根据已验证结果同步计划与验收状态 |

Grok Bot 不直接修改代码、不运行格式化写回、不提交 Git。需要修改时，在 `docs/GROK_REVIEW.md` 中给出证据和验收标准，由 Codex 复核后执行。

## 一轮协作流程

1. Codex 在 `CODEX_HANDOFF.md` 写明当前状态、测试结果和需要审查的问题。
2. Grok Bot 只读检查代码、差异和相关文档，把结论写入 `GROK_REVIEW.md`。
3. 用户在 Codex 中说“读取 Grok 评审并继续”。
4. Codex 对每条意见先复现或查证，再修改代码和补测试。
5. Codex 更新交接文件，Grok Bot进行下一轮复核。

如果 Grok Bot 无法写文件，可把同样格式的回复复制到 Codex 对话中。

## 审查要求

每轮最多提交 5 个高价值问题，按 P0、P1、P2 排序：

- P0：卡死、崩溃、存档损坏、无法推进、输入失效。
- P1：明显影响战斗判断、动作协调、UI 可读性或新玩家理解的问题。
- P2：观感、措辞、微动效、低频边界和后续扩展建议。

每个问题必须包含：

1. 证据：文件与行号、测试输出、截图位置或可观察现象。
2. 复现步骤：从哪个状态开始、按什么操作、出现什么结果。
3. 期望结果：玩家应该看到或感受到什么。
4. 修改建议：优先给最小、可验证的方案，不直接写入代码。
5. 验收标准：至少一条自动测试或明确的人工检查方法。
6. Codex 指令：一段可直接执行、边界明确的任务描述。

仅有主观判断而没有证据的建议标为“观察项”，不得列为阻断问题。

## 合并与质量门槛

- Codex 修改前先检查工作区，保留用户和其他工具已有改动。
- 每项实现至少运行对应专项测试；跨主流程改动还需运行完整 smoke 集。
- 当前完整基线为 48 项 smoke 测试通过。
- Windows 全屏、Alt+Tab、125%/150% 缩放、手柄断连重连仍属于实机验收，不得用无头测试冒充完成。
