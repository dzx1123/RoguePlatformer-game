# 平衡版本记录

## 0.5.0-p6-content · 2026-09-03

状态：P6 内容深度与构筑成长的基线版本。

本版本接入了由最近 60 次路线记录生成的平衡审查。审查只给出可复查的信号和建议，不会自动改动伤害、血量或生成预算，避免小样本导致错误削弱或增强。

### 数据口径

- 武器：起始武器的局数、胜场和通关率。
- 强化：每项强化的出现次数、被选择次数和选择率。
- 房间：遭遇类型的样本数、平均耗时、平均承伤和死亡率。
- 数据源：user://run_telemetry.json，仅保留最近 60 次已结束路线。

### 触发阈值

| 目标 | 最低样本 | 需要复查的信号 |
| --- | ---: | --- |
| 武器 | 8 局 | 选择量低于均分的 60%、或通关率偏离总体 12% 以上 |
| 强化 | 12 次出现 | 选择率低于 22%、或高于 56% |
| 房间 | 8 间 | 平均耗时高于 42 秒、或死亡率高于 28% |

### 审查动作

- improve_discoverability：先检查武器解锁节奏、提示和专属强化出现条件。
- consider_buff / consider_nerf：通过一项小幅数值或冷却调整验证，不同时改多个维度。
- consider_buff_or_reword：先修正强化描述、适用场景或上下文提示，再评估数值。
- reduce_time_budget：减少波次、精英配额或追击间隔。
- reduce_damage_or_improve_telegraph：降低不可预期承伤，或增加地面/远程预警时间。

### 当前结论

这是首个 P6 基线记录。项目尚未把真实玩家样本写入仓库，因此不依据虚构数据做武器强弱调整；达到上述最低样本后，从 RunTelemetry.get_balance_review() 导出的信号开始逐条记录调整原因、改动值、样本区间和回归结果。
