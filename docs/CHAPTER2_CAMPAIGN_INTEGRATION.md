# 两章连续旅程接入

更新：2026-09-18。本文件覆盖旧文档中“第一章胜利后手动选择第二章”的阶段描述。

## 正式路线

第一章最后房间完成后直接进入第 21 房，不打开胜利结算，不入账星屑。继承种子、轮次、武器、强化、生命及上限、金币、难度、命数、本局星屑。第二章沿用同一遥测对象；重新加载时从持久化数据恢复。内部按章节存储检查点，但对玩家是同一局旅程；保存第二章成功后移除旧第一章继续档。

第二章正式路线不允许 R/F2 免费回血重试。死亡返回 Main 的现有失败回顾，扣除一条命、结算失败所得，按第一章规则从第一章重开；命数耗尽重新选难度。完成第 40 房后才进入 Main 的整局胜利结算。重复调用胜利结算不会再次入账。新开正式旅程会清除上一局的第二章继续档。

难度使用第一章 CombatBudget 的末段倍率调整第二章敌人生命和攻击，包括投掷物；环境热区维持固定伤害。整章武器平衡仍需实战验证。

## 开发入口

主菜单“开发测试 · 第二章”保留，测试档使用 `.test` 后缀，与正式档隔离；可独立反复测试。正式继续档优先于测试档。旧第二章试玩档可继续作为旧试玩，不伪装成具有第一章继承状态的正式旅程。

## UI

连续路线直接复用第一章 RunHUDBuilder 与 RunHUDPresenter 的血条、命数、货币、技能冷却、武器栏、房间与首领血条；房间总数显示 40。暂停和事件面板使用同一 MoonUI 样式。最终胜利、死亡回顾直接使用第一章界面。第二章暂停界面的设置/构筑查看等完整功能尚需继续统一，当前已支持继续和保存退出。

## 验证

`chapter2_campaign_smoke` 验证：真实场景切换、跨章不结算、状态继承、入场后移动、JSON 检查点重建、困难敌人生命倍率、禁用免费重试、死亡扣命后重开第一章、最终结算与重复结算保护。源码与导出 PCK 均通过。`test_output/chapter2_campaign_hud.png` 为连续路线实际 HUD 截图。

最新包：`build/campaign-connected/EmberForge.exe`。测试使用快速击败首领，不代表四十房正常伤害人工通关。应用在写入终态与局外结算之间被强制关闭的恢复仍需补强；当前不宣称崩溃事务已完整实现。
