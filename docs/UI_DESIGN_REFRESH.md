# UI 设计基线

更新时间：2026-09-07
状态：已实现，作为后续 UI 修改和回归检查的设计规范。

视觉稿见 [UI_MOCKUPS.md](UI_MOCKUPS.md)。视觉稿用于表达层级和气质；当前代码、1280×720 画布及无障碍约束优先于旧稿的像素位置。

## 基础约束

- 设计画布：`1280 × 720`，16:9。
- 关键文字和可交互控件保持安全边距，不依赖屏幕裁切区域。
- 中文为玩家界面的主要信息；英文只可作为低透明度装饰。
- 一屏一个主焦点：标题页为继续/开始，奖励页为当前卡片，战斗 HUD 为生命与危险，结算页为主要行动按钮。
- 动效位移短且可预测；开启减弱效果时只保留必要淡入淡出与危险提示。
- 键盘和手柄焦点必须同样可见，不能只依赖鼠标悬停。

## 颜色叙事

- 探索与普通强化：月弧青。
- 商店与货币：星尘金。
- 事件与未知取舍：月蚀紫。
- 胜利、安全和恢复：安全翠。
- 伤害、风险和失败：危险红。

危险红不用于普通成功确认。色觉辅助开启后，生命、首领、货币、伤害数字和击败反馈切换为青/橙/金的可分辨组合，不能只依赖红绿差异。

## 界面层级

### 标题与难度

- 标题页突出继续或开始，设置和退出保持次级。
- 难度卡横向排列，当前焦点通过顶条、亮度和轻微抬升共同表达。
- 标题和难度页暂停玩法树，HUD 输入桥保持响应。

### 战斗 HUD

- 底部信息坞从 `y=640` 开始，占 80 px；左侧生命/命数/货币，中间动作冷却，右侧武器。
- 左上只保留房间与种子 Caption；首领生命条居中置顶。
- 短状态使用底栏上方单行芯片，自动淡出；模态页面开启时隐藏战斗信息。
- 奖励确认条不得添加全屏遮罩，也不得遮挡关键战斗区域。

### 奖励层

- 强化、商店、事件和胜利复用同一骨架，以颜色、标题和卡片信息区分。
- 卡片使用顶边强调和清晰焦点，不靠四边高亮描边堆层级。
- 商店明确价格和金币不足；事件明确收益与代价；结算明确主要与次要行动。

### 暂停、设置与复盘

- 暂停层只保留继续、构筑、设置和返回标题等明确动作。
- 设置项分组，显示与辅助选项在大号字下不得重叠。
- 死亡复盘保持可读，玩家明确选择再次挑战或返回标题后才离开。

## 修改边界

- 优先复用 `ui_theme.gd`、HUD builder/presenter 和现有奖励组件。
- 不因局部 UI 改动大拆 `main.gd` 或改变战斗数值。
- 不新增字体包、背景大图或动效系统，除非对应资源和需求已经确定。
- 修改后运行相关 UI、输入、分辨率和无障碍测试，并补人工截图检查。
