## 总判断

系统面已经够一个完整测试包：20 房、种子、三武器、强化、首领阶段、遥测、存档恢复、手柄、设置。P0–P2、P5、P6 按路线图视为完成。

玩家更容易觉得「像很完整的原型」，而不是「像一款记得住的游戏」。主要原因：

1. 砍上去的重量不够（缺顿帧时尤其明显）。
2. 房间、强化、事件记忆点偏薄。
3. 第一局和失败后的说明不完整。
4. 音乐仍是程序氛围，多数世界事件没有独立采样。

缺口不在再堆系统，而在手感、个性和第一局产品体验。

## 能力边界

能主导：

- 状态机时长、取消窗口、pose 混合、hitstop、击退、镜头、音效触发与分层
- 按现有画布规范接入新帧，并用帧审计测试拦住脚滑和抽帧
- 存档、继续、复盘、引导、事件取舍等流程

不能替代：

- 画新角色/敌人帧，或把草图变成符合规范的正式像素
- 作曲、编曲、录音、拟音
- 只靠插值把 8 帧跑步变成 24 帧电影级流畅
- 不看实机、不听耳机就把打击感一次调到发行级

新动画和音乐是放大器。帧不够时，代码只能做到「不抽」，做不到「更细」。

## 优先级（按玩家观感，不是按实现难度）

### 第一轮：不依赖新原画，对试玩观感最大（0.4.1 已落地）

1. 命中顿帧、空挥/实砍音量差、攻击命中后的冲刺取消
2. 死亡复盘（用已有遥测）+ 第一房短引导
3. 音频事件表：落地、脚步、开箱、进门、UI；BGM 按菜单/探索/战斗/首领分状态
4. 事件房改成真正取舍，不再三张纯奖励
5. 房间边界的中途继续

### 第二轮：和新动画、UI 打磨并行

- 保持现有画布/锚点，新帧先过 `character_frame_spec_smoke` 和 `animation_motion_audit`，再改进度点
- 商店 / 事件 / 胜利页并进同一套奖励层 UI
- 补齐仍缺的音频采样（见音频计划），程序占位只换文件、不改触发
- HUD 留白、字号、信息优先级统一

### 第三轮：有真实试玩数据后再做

- 武器和强化数值（遥测管线已有，仓库里还没有真实玩家样本）
- 成就、图鉴、每日种子
- 第三族敌人、大量新房间

### 明确先不要做

- 没有新功能驱动时，不要为架构漂亮把 `main.gd` 大拆
- 没有采样就先上完整配乐工程
- 在没有玩家样本时做一轮大数值平衡
- 没有新帧时，不要指望再调混合时间能明显提高跑步细腻度

## 技术债（有功能需求再动）

- `main.gd` 仍约 3500+ 行，同时管房间、战斗、相机、菜单、设置。房间目录、遭遇、强化、HUD 已拆出。没有新系统时不主动大拆。
- `Main.tscn` 仍留原型文案 `ROGUE PLATFORMER / PROTOTYPE 01`，运行时会被 HUD 构建器藏掉。
- 测试包版本曾与平衡记录不一致（0.4.x 对 0.5.0-p6）。对外以 `BUILD_LABEL` 和 [TEST_BUILD_NOTES.md](TEST_BUILD_NOTES.md) 为准。
- 没有崩溃日志和版本迁移策略。存档已有原子写入和备份。
- 性能目前不是主问题：30 分钟压力测试峰值约 248 节点、139 MiB。
