# 近期执行计划

更新时间：2026-09-07
目标：先把当前版本验证成可稳定交付的测试包，再用真实反馈决定下一项内容投入。

项目已经具备完整的一局骨架。当前缺口不在继续堆系统，而在发行环境可信度、真实玩家反馈和少量高辨识度内容。

## 执行原则

1. 按“发布验收 → 试玩采样 → 数据复盘 → 单项内容增强”推进。
2. 每次只开一个可以独立验收的切片；先写验收标准，再改实现。
3. 自动测试只证明可重复逻辑，画面、听感、DPI 和实体设备必须人工检查。
4. 计划状态以 [ROADMAP.md](ROADMAP.md) 为准，专项参数以对应规范为准。
5. 不以重构、增加文档或增加测试数量代替玩家可感知的改进。

## 阶段 A：Windows 发布收口

### 工作

1. 按 [WINDOWS_RELEASE_CHECKLIST.md](WINDOWS_RELEASE_CHECKLIST.md) 完成人工显示矩阵。
2. 用实体手柄覆盖标题、设置、战斗、奖励、暂停、死亡与胜利路径。
3. 在独立 Windows 机器验证发行包启动、存档恢复和用户数据保留。
4. 只修复实际复现的 P0/P1 问题；修复后跑专项测试和完整回归。

当前自动化进度：模拟 Xbox 输入已覆盖摇杆阈值、键鼠提示切换、连接回调焦点恢复和主要按键路径；真实 Windows 窗口中的 GUI 中心点注入点击已覆盖标题、难度、设置、暂停、奖励、死亡和胜利。以上只关闭软件逻辑缺口，不替代实体鼠标、实体手柄和多 DPI 人工验收。

### 退出条件

- 100%/125%/150% DPI 无关键文字裁切或不可点击控件。
- 全屏、Alt+Tab、最小化/恢复后画面、音频和输入正常。
- 手柄断连重连后提示与焦点能够恢复。
- 独立机器无需 Godot 即可启动，并能跨重启读取进度和设置。
- 发布包对应明确的 Git 提交、版本和测试记录。

## 阶段 B：真实试玩采样

### 工作

1. 先观察玩家能否独立完成开局、首个事件、首次死亡和首次首领。
2. 记录种子、难度、武器、终止房间、死因、房间耗时和口头困惑。
3. 收集三把武器的有效路线样本；未达到 [BALANCE_RECORD.md](BALANCE_RECORD.md) 门槛前只记录，不改数值。
4. 把 UI、输入、动作和音频反馈分开记录，避免把“不明白”误判成“太难”。

### 退出条件

- 至少完成一轮外部试玩复盘。
- 每个准备比较的武器达到最低样本量。
- 形成最多 5 个带复现步骤和验收标准的高价值问题。

## 阶段 C：选择一个内容增强切片

按试玩证据从以下方向只选一个：

### 房间辨识度

- 按章节增加背景或调色变化。
- 优先制作 2–3 个记忆房间，不批量堆相似平台布局。

### 事件变化

- 按章节拆分事件池。
- 增加能改变下一房遭遇或奖励风险的选项。

### 武器构筑变化

- 每把武器优先增加一项改变操作或技能形态的强化。
- 不继续只叠加范围、伤害和冷却。

### 新手理解

- 仅在试玩确认需要时，渐进提示冲刺、技能、上劈和下劈。
- 保持非阻断，不制作强制停顿教学房。

## 阶段 D：素材驱动的进一步打磨

- 有新角色帧时按 [CHARACTER_ANIMATION_SPEC.md](CHARACTER_ANIMATION_SPEC.md) 接入，再依据实机画面调整命中进度。
- 有更高质量音频素材时按 [AUDIO_PLAN.md](AUDIO_PLAN.md) 替换稳定路径，不改变既有事件触发。
- 没有新素材或真实反馈时，不继续微调已经通过验收的混合参数。

## 明确不做

- 不自动打包或覆盖已有发行物。
- 不在没有玩家样本时开展大范围平衡调整。
- 不为“架构更漂亮”大拆 `main.gd`。
- 不提前开发成就、图鉴、每日种子、第三敌人族群或多存档系统。
- 不保留一次性交接、审查往返或已完成切片的实施说明；历史由 Git 保存。
